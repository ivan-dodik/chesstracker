# Правило работы по Implementation Plan

Агент **обязан** следовать `IMPLEMENTATION_PLAN.md` при реализации проекта.

## Обязанности агента

1. **В начале каждой сессии** — прочитать `IMPLEMENTATION_PLAN.md` и Memory Bank (core-файлы):
   - `memory-bank/projectbrief.md`
   - `memory-bank/productContext.md`
   - `memory-bank/activeContext.md`
   - `memory-bank/systemPatterns.md`
   - `memory-bank/techContext.md`
   - `memory-bank/progress.md`

2. **Каждый tool use** — обновлять `task_progress`:
   - Использовать параметр `task_progress` в каждом вызове инструмента
   - Указывать текущее состояние чекмаков из `IMPLEMENTATION_PLAN.md`
   - Отмечать выполненные шаги как `[x]`, активный шаг без галочки
   - Обновлять список, если в процессе открылись новые подзадачи

3. **После каждого шага** (или группы из 2-3 тесно связанных шагов) — обновить файлы документации:
   - `CHANGES.md` — добавить запись в конец файла (дата, время, описание изменений, затронутые файлы)
   - `PROMPTS.md` — добавить запись, если пришёл новый промпт от пользователя
   - `REPORT.md` — добавить запись в раздел «История работы»

4. **После каждого майлстоуна** (M1–M11) — выполнить:
   - Обновить `REPORT.md`:
     - Добавить запись в раздел «История работы» о выполненных шагах майлстоуна
     - Зафиксировать возникшие проблемы в разделе «Ключевые проблемы и решения»
     - Дополнить раздел «Удачные и неудачные шаги» при необходимости
   - `git add -A`
   - `git commit -m "<тип>: <описание>"` (согласно `.clinerules/git_commit.md`)
   - `git push`
   - Обновить Memory Bank:
     - `activeContext.md` — текущее состояние, след. шаги
     - `progress.md` — отметить выполненные майлстоуны, обновить статус
     - Другие файлы, если были значимые архитектурные решения

5. **Отслеживание прогресса** в task_progress:
   - Формат: полный список чекмаков из плана с актуальными отметками
   - Если майлстоун начат, но не завершён — отмечать только завершённые шаги внутри него
   - Если майлстоун завершён — отмечать `[x]` заголовок майлстоуна и все его шаги

## Структура task_progress

```
- [x] M1: Архитектура и планирование
  - [x] Создать ARCHITECTURE.md
  - [x] Убедиться, что IMPLEMENTATION_PLAN.md актуален
  - [x] Обновить Memory Bank
- [ ] M2: Окружение и Docker
  - [x] Шаг 1 (выполнен)
  - [ ] Шаг 2 (в работе)
  - [ ] Шаг 3
...
```

## Исключения

- Если пользователь явно попросил **не следовать плану** — игнорировать это правило.
- Если план устарел и требует изменений — сначала обновить `IMPLEMENTATION_PLAN.md`, затем продолжить.
- Если возникла проблема, не описанная в плане (например, ошибка в коде) — исправить, зафиксировать в REPORT.md («Ключевые проблемы и решения») и продолжить по плану.
