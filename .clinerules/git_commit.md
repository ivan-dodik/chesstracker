# Правила коммита и документирования

## Коммит и пуш

При завершении задачи (перед вызовом `attempt_completion`) агент **обязан** выполнить коммит всех изменений и пуш.

### Процедура

1. **Проверить статус** — `git status`.
2. **Проверить актуальность документации** — перед коммитом убедиться, что:
   - `CHANGES.md` — запись в конце файла (дата, описание, затронутые файлы)
   - `PROMPTS.md` — запись о новом промпте (если был)
   - `REPORT.md` — запись в «История работы»; при необходимости — «Ключевые проблемы», «Удачные/неудачные шаги»
   - Memory Bank (`activeContext.md`, `progress.md`) — актуальны
3. **Сгенерировать описание коммита** — формат: `<тип>: <краткое описание>`
   - Типы: `feat` / `fix` / `docs` / `chore` / `refactor` / `test` / `style`
4. **Добавить файлы** — `git add -A` или точечно
5. **Коммит** — `git commit -m "<сообщение>"`
6. **Пуш** — `git push`

### Исключения

- `git push` ошибка → коммит локально + сообщить пользователю
- Пользователь попросил не коммитить → пропустить

### Важно

- Атомарный коммит: одна задача — один коммит
- Сообщение отражает суть изменений
- Не коммитить файлы из `.gitignore`

## Документирование проекта

### История промптов (PROMPTS.md)

Все промпты сохраняются в `PROMPTS.md` с указанием:
- Дата, время (YYYY-MM-DD HH:MM), контекст запроса
- Режим агента (Plan / Act)
- Текст промпта (промптов, если серия)
- Ответ агента (в Plan-режиме)
- Результат выполнения

### История изменений (CHANGES.md)

Все изменения документируются в `CHANGES.md`:
- Дата, время (YYYY-MM-DD HH:MM)
- Описание изменений
- Созданные/обновлённые файлы
- Записи добавляются в **конец файла**

### Отчёт (REPORT.md)

Записи в «История работы» после каждого завершённого шага. При проблемах — в «Ключевые проблемы и решения» и «Удачные/неудачные шаги».

### Правило обновления

PROMPTS.md, CHANGES.md и REPORT.md **обновляются после каждого завершённого шага** (одного tool use или группы связанных tool use):

1. После создания/изменения файлов, выполнения команд/тестов → CHANGES.md
2. После нового промпта от пользователя → PROMPTS.md
3. После завершённого шага → REPORT.md («История работы»)
4. Перед `attempt_completion` → проверить актуальность всех файлов
5. Перед `git push` → повторно проверить все файлы + Memory Bank
