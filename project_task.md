# Шахматный трекер турниров и рейтингов (Chess Tracker)

**Проект:** Full-stack приложение для отслеживания шахматных турниров, игроков и их рейтингов. Сервис помогает шахматным болельщикам следить за выступлениями любимых игроков на офлайн-турнирах, отслеживать изменения рейтингов и получать уведомления о результатах партий.

---

| Компонент                | Технология                                            |
| ------------------------ | ----------------------------------------------------- |
| Backend                  | Python 3.12+, FastAPI                                 |
| База данных              | PostgreSQL 16                                         |
| ORM / миграции           | SQLAlchemy + Alembic                                  |
| Фронтенд                 | Jinja2 + HTMX + Alpine.js (SPA-подобный UX без React) |
| Telegram-bot             | python-telegram-bot                                   |
| Управление зависимостями | uv                                                    |
| Линтер                   | ruff (flake8 + isort + pyupgrade в одном)             |
| Docker                   | docker compose (backend, frontend, db, telegram-bot)  |
| CI                       | GitHub Actions (ruff lint + pytest)                   |
| API-документация         | Swagger UI (встроенный в FastAPI, `/docs`)            |

## Функциональные требования

### Общие

- **CRUD** основных сущностей (игроки, турниры, партии) с валидацией на клиенте и сервере
- **Поиск и фильтрация**:
  - Турниров по дате, местоположению, статусу (активный / завершённый)
  - Игроков по имени, рейтингу, городу
- **Дашборд с визуализацией** (Chart.js):
  - График изменения рейтинга игрока
  - Круговая диаграмма результатов (победы / ничьи / поражения)
  - Топ-10 игроков по рейтингу
  - Избранные игроки
- **Пагинация** списков
- **Адаптивная вёрстка** (desktop + mobile)

### Специфичные

- **Турниры**: создание / редактирование (название, даты, место проведения, количество туров, тип — классика / блиц / рапид), просмотр турнирной таблицы в реальном времени
- **Игроки**: профиль с историей рейтинга (хранимое число, в будущем — из внешнего API), списком сыгранных турниров, статистикой (очки, место, процент побед)
- **Партии**: ввод результатов по турам, автоматический подсчёт очков, обновление турнирной таблицы
- **Рейтинговая история**: срезы рейтинга на дату, отслеживание изменений после каждого турнира
- **Статистика**: head-to-head (личные встречи двух игроков), общая статистика побед / поражений / ничьих
- **Избранные игроки**: добавление в избранное, вкладка с активными турнирами и последними результатами
- **SSE (Server-Sent Events)**: уведомления в реальном времени при добавлении результата партии
- **Экспорт турнирной таблицы в CSV**
- **Импорт результатов турнира из CSV** (маппинг колонок: игрок, тур, соперник, результат)
- **Регистрация / авторизация (JWT)**: два предзаполненных аккаунта — администратор (CRUD турниров и партий) и обычный пользователь (просмотр, избранное)
- **Лог активности**: фиксация всех изменений (создание / редактирование турнира, результат партии, изменение рейтинга) с пользователем, временем и значениями до / после
- **Telegram-bot**: уведомления о результатах партий и изменениях в активных турнирах (отдельный микросервис в docker compose)

## Нефункциональные требования

- **REST API с OpenAPI / Swagger** — живая веб-страница по `/docs`
- **Не менее 10 unit / integration тестов**
- **CI pipeline (GitHub Actions)**: ruff lint + pytest; опционально — сборка Docker-образа
- **Docker Compose**: одна команда `docker compose up` запускает backend + frontend + БД + telegram-bot
- **README.md** — инструкция по запуску (markdown)
- **ARCHITECTURE.md** — описание архитектуры, ERD, план разработки (создаётся до кодирования, подтверждается git-историей)
- **REPORT.md** — история создания проекта, ключевые проблемы, промпты, решения (заполняется по ходу)
- **Адекватная история коммитов** — не всё одним коммитом

## Seed-данные

- 5 турниров (3 завершённых, 2 активных)
- 30+ игроков
- 200+ партий
- 50+ записей истории рейтингов
- 2 пользователя (admin + user)

## Процесс разработки

- Все промпты и изменения документируются в `PROMPTS.md` и `CHANGES.md`
- Каждый завершённый шаг (один или группа связанных tool use) фиксируется в обоих файлах
- Управление зависимостями — через `uv` (pyproject.toml, uv.lock)
- Линтер — `ruff` (в CI и pre-commit)
- Прогресс фиксируется в REPORT.md согласно требованиям, в человекочитаемом виде.
